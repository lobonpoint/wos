# Email intake and processing

This folder is a **local processing workspace**, not a mailbox connector. **Do not put real workplace email here unless your organization explicitly approves the storage location and Copilot processing.** All contents of the five data directories except `.gitkeep` are ignored by Git. Keep corporate data in a separately approved checkout/storage location when possible.

| Directory | Purpose |
|---|---|
| `intake/` | Drop approved `.eml` / `.msg` exports to be processed |
| `processed/` | Files archived after successful import or known duplicates |
| `failed/` | Files that could not be parsed/imported, with reasons in the command output |
| `drafts/` | Human-reviewed proposed replies (initially manual, not generated by the CLI) |
| `reports/` | Per-batch import summary (no email body text) |

## Workflow

```powershell
python -m wos init
# Copy approved exported messages to email/intake/
python -m wos email-process
python -m wos list actions
python -m wos list project_proposals
python -m wos brief
```

`email-process` scans only the top level of `email/intake/`, skips other extensions, and processes each `.eml` or `.msg`. It moves successful imports and duplicates to `processed/` with collision-safe filenames. Files with import errors move to `failed/`. A short JSON batch report is saved in `email/reports/`. This command never connects to Outlook, sends mail, or automatically approves project proposals.

You can still import explicit files directly with `python -m wos email-import path/to/export.eml`; that operation does not move the original.

**Security:** `.gitignore` helps avoid accidental inclusion in Git but is not DLP. Check `git status` and `git ls-files email` before any push; never use `git add -f` on workplace data.
